内容中台 · 功能文档（运维版）

面向系统使用 / 运维操作的同事 — 假设你能看懂 JSON、用 curl，但不需要看源码
面向：运营 / 内容审核 / 平台运维 不涉及：源码内部结构、agent 实现细节

1. 系统是什么

一条 8 步内容流水线：从外部信源采集内容 → 自动整理 → 合规审核 → 人工放行 → 发布到自有站点 → 改写后分发到社媒 → 数据回流。

① 信源打分 ② 采集 ③ 分类+起标题 ④ 配封面 ⑤ 合规审核 ⑥ 发布* ⑦ 分发* ⑧ 数据回流

* 是硬人工闸口，自动模式永远不会触发，必须通过后台手动放行。

谁在生效

  • 调度器 定时拉任务（采集每小时、数据回流每天 2 点）
  • auto-pipeline 每 15 秒扫一次队列，给"自动模式开启"的 agent 自动补单
  • 告警 poller 监控队列堆积和失败率，超阈值发 Sentry / 通知

2. 8 个 Agent 速览

[1]

source-scoring · 信源打分

做什么
根据产出量、合规通过率、PV、收入打分（0-100），决定信源在采集阶段被选中的概率
触发
auto-pipeline 自动；手动 POST /admin/day5/score-now
影响
更新 sources.score / risk_level / status
注意
分数 < 20 自动暂停；连续合规失败 ≥ 20 自动拉黑
[2]

ingestion · 采集

做什么
从激活信源拉新内容，去重清洗后入库
支持平台
RSS · HTML · Reddit · Bluesky · X · Knit · 2ksg · Sitemap
触发
cron 0 * * * * 自动；手动 POST /admin/ingest/fanout
三层去重
① URL dedupe_key　② 源内 content_hash 完全相同　③ 源内 simhash 模糊匹配（汉明距离 ≤ 3）
失败模式
认证失败抛 AdapterAuthError，/admin/sources/auth-status 可查
[3]

classify-title · 分类 + 起标题

做什么
用 LLM 给文章打 category + tags + keywords，再生成多个标题候选挑最优 + 摘要 + slug
降级
关键词分类 + 保留原标题（环境变量 CLASSIFICATION_SKIP_LLM=1 · TITLE_SKIP_LLM=1）
幂等
重跑只会升 title_version，不会重复触发下游
[4]

cover · 封面

做什么
从原文图片中按分辨率 + 长宽比挑最优，压缩多尺寸传 S3，生成封面文案
反盗链
对 2ksg/knit/x 等源自动加 Referer / Cookie
HTML 源
额外取 Top-6 图作为图集（gallery）
降级
cover_copy 用文章标题（COVER_SKIP_LLM=1）
[5]

compliance · 合规审核

做什么
L1 正则黑名单 + L2 LLM 6 维度打分（0-3）
6 个维度
政治敏感 · 色情低俗 · 暴力恐怖 · 版权争议 · 医疗夸大 · 金融诱导
判决
黑名单命中 → FAIL · 最高分 ≥ 3 → FAIL · ≥ 2 → REVIEW · 其他 → PASS
降级
COMPLIANCE_SKIP_LLM=1：黑名单干净就自动 PASS
[6]

publishing · 发布

人工闸口
做什么
写 published_url + published_at，触发 Next.js ISR 刷新四个路径
触发
仅人工：POST /admin/pipeline/approve-publish 或 admin UI
strict 模式
PUBLISH_STRICT=1 时仅 COMPLIANCE_PASS 可发布；默认宽松（兼容历史数据）
失败容忍
revalidate 失败不阻塞发布（fire-and-forget）
[7]

distribution · 社媒分发

人工闸口
做什么
为已发布文章生成社媒文案，写入 distribution_tasks 等执行
当前渠道
twitter（X）。280 字符预算，结尾 2-3 hashtag
降级
规则版改写：标题截断 + tag → hashtag + 链接（DISTRIBUTION_SKIP_LLM=1）
实际投递
当前只入库；外部 worker 消费 distribution_tasks WHERE status='pending'
[8]

analytics · 数据回流

做什么
每天拉 GA4 昨日数据；每周生成 markdown 报表
需要
GA4_PROPERTY_ID + GOOGLE_APPLICATION_CREDENTIALS
缺凭证
静默降级，回流 0 条，但不影响其他流程
反哺
结果作为 source-scoring 的 PV / 收入加分项

3. 状态机

状态含义谁会处理
INGESTED刚采集回来classify-title 接手
CLASSIFIED已分类，等起标题classify-title 续跑
TITLED已起标题、有 slugcover 接手
COVERED已配封面compliance 接手
COMPLIANCE_PASS合规通过等人工放行发布
COMPLIANCE_REVIEW合规拿不准需人工审核
COMPLIANCE_FAIL合规拒绝不会自动往后走
PUBLISHED已上线网站等人工分发
DISTRIBUTED已分发到至少一个社媒终态
状态守门：每个 agent 都检查 items.status 是否在允许列表内，串错状态会自动跳过（返回 {skipped:true}），不会导致重试浪费。

表用途关键字段

5. 配置面板（环境变量）

降级开关（最常用）

变量启用后
CLASSIFICATION_SKIP_LLM=1关键词规则分类，不调 LLM
TITLE_SKIP_LLM=1用原标题，不调 LLM
COVER_SKIP_LLM=1cover_copy 用文章标题
COMPLIANCE_SKIP_LLM=1仅黑名单审核，干净就 PASS
DISTRIBUTION_SKIP_LLM=1规则版推文（标题 + hashtag + 链接）

调度

AUTO_PIPELINE_INTERVAL_MSauto-pipeline 扫描间隔，默认 15000
INGESTION_CRON采集 cron，默认 0 * * * *
ANALYTICS_CRON数据回流 cron，默认 0 2 * * *
DISABLE_AUTO_PIPELINE=1关闭 auto-pipeline（仅手动触发）
DISABLE_SCHEDULER=1关闭 cron

告警阈值

ALERT_QUEUE_THRESHOLD队列堆积告警阈值，默认 100
ALERT_LLM_FAIL_RATELLM 失败率告警阈值，默认 0.15
ALERT_INTERVAL_MINUTES告警检查频率（分钟），默认 5

发布

PUBLISH_STRICT=1仅 COMPLIANCE_PASS 可发布
WEB_URLpublishing 调 ISR 刷新的内部地址
REVALIDATE_SECRETISR 鉴权 secret
SITE_URL对外公开站点 URL（写入 published_url）
改完环境变量必须重启 API 服务才生效。线上改 env 走运维流程；测试环境直接重启 dev 进程即可。

6. 控制层（Pipeline 控制）

三套独立的开关：

层级开关影响
全局 急停 / 恢复 暂停所有 agent 调度，运行中的 job 不打断
单 agent · 自动模式 auto on/off auto-pipeline 是否自动给该 agent 补单
单 agent · 暂停 paused on/off 该 agent 不消费新任务（已在 active 的不影响）
publishing 和 distribution 永远不会被 auto-pipeline 触发，无论 auto on/off 状态如何 — 这是写在代码里的硬约束，避免误发。

8. 安全 / 风险点

  • 合规人工放行的责任：REVIEW 列表里你点放行就等于背书。系统不可能 100% 准确，最终判断在人。
  • 分发不要过快：短时间内推太多到同一社媒账号容易触发对方风控。建议带间隔。
  • LLM 调用是花钱的：每次调用进 agent_runs.cost_usd。SELECT SUM(cost_usd) FROM agent_runs WHERE started_at > now() - interval '1 day' 看日均开销。
  • HARD_HUMAN_GATES 不要绕过：publishing 和 distribution 的人工闸口是写死的，任何"自动发布"诉求都应该重新设计审核流程，而非直接绕过。
  • 急停影响范围：急停只停"调度"，已被 worker 拿出来处理的 job 会跑完。如果要打断正在跑的任务，需要重启 API 服务。
