CH 内容中台 · 使用说明

从零起项目到日常运维的最短路径

1. 起项目（5 分钟）

1准备环境 
# 需要 Node ≥ 20.10 + pnpm 9 + Docker
node --version && pnpm --version && docker --version
2配置环境变量 
cp .env.example .env
# 至少填 GROQ_API_KEY；不填的话用 SKIP_LLM 也能跑
3起基础设施 + 装依赖 + 跑迁移 
pnpm infra:up      # Postgres + Redis + MinIO
pnpm install
pnpm migrate
4启动开发环境 
pnpm dev
# API → http://localhost:4000
# Web → http://localhost:3000
# Admin → http://localhost:3000/admin
5验证 
curl http://localhost:4000/health
# → {"ok":true,"ts":...}
端口：Postgres 在宿主 5433，Redis 在 6381，MinIO 在 9002/9003（避开 macOS 上的常见占用）。.env 里的连接串用这套端口。

2. 日常使用

添加一个信源

curl -X POST http://localhost:4000/admin/sources \
  -H 'content-type: application/json' \
  -d '{
    "platform": "rss",
    "external_id": "techcrunch",
    "name": "TechCrunch",
    "url": "https://techcrunch.com/feed/",
    "config": {}
  }'

立即触发一轮采集

curl -X POST http://localhost:4000/admin/ingest/fanout

看流水线状态

curl http://localhost:4000/admin/stats
curl http://localhost:4000/admin/pipeline/state
curl http://localhost:4000/admin/pipeline/live-jobs

放行人工闸口

发布和分发是硬人工卡点，需要手动放行：

  • 合规 REVIEW 列表 → /admin/pipeline/review-queue → 调 approve-review/:itemId
  • 等发布 → /admin/pipeline/publish-queue → 调 approve-publish
  • 等分发 → /admin/day6/distribute/:id 或批量 /admin/day6/distribute-all

用 Web 控制台

/admin总览
/admin/day3分类 + 标题
/admin/day4封面 + 合规
/admin/day5发布 + 信源打分
/admin/day6分发 + 数据
/admin/day7监控 / 告警 / 灰度
/workbench流水线工作台

3. 常用命令

命令作用
pnpm devAPI + Web 一起起
pnpm infra:up / infra:down / infra:logs起 / 停 / 看基础设施
pnpm migrate跑数据库迁移
pnpm seed灌种子数据
pnpm --filter @ch/api exec tsx scripts/test-all-agents.ts跑 7 个 agent 综合测试
pnpm --filter @ch/api exec tsx scripts/test-classify-title.ts跑 classify-title 单 agent 测试
scripts/retry-failed.ts批量重试失败任务
scripts/clear-failed.ts清空 failed 队列
scripts/inspect-failures.ts看最近失败原因

4. 关键开关

降级模式（无 LLM 配额时用）

# 都加在 .env 里，改完重启 API
CLASSIFICATION_SKIP_LLM=1   # 分类走关键词
TITLE_SKIP_LLM=1            # 标题用原标题
COVER_SKIP_LLM=1            # 封面文案用标题
COMPLIANCE_SKIP_LLM=1       # 合规黑名单干净就 PASS
DISTRIBUTION_SKIP_LLM=1     # 推文用规则版改写

关闭自动调度

DISABLE_AUTO_PIPELINE=1   # 不自动 enqueue agent
DISABLE_SCHEDULER=1       # 不跑 cron

严格发布

PUBLISH_STRICT=1   # 仅 COMPLIANCE_PASS 可发布

5. 急停与恢复

# 全局急停（所有 agent 暂停调度，正在跑的 job 不打断）
curl -X POST http://localhost:4000/admin/pipeline/emergency-stop

# 恢复
curl -X POST http://localhost:4000/admin/pipeline/resume

# 暂停单个 agent
curl -X POST http://localhost:4000/admin/pipeline/set-paused \
  -H 'content-type: application/json' \
  -d '{"agent":"compliance","paused":true}'

6. 出问题怎么查

现象查这里
API 起不来 docker compose ps 看容器；确认 .env 端口对得上 5433/6381/9002
队列堆积 GET /admin/day7/queues；GET /admin/pipeline/state 看是否被暂停
某 item 卡住 GET /admin/pipeline/item-history/:itemId 看 agent_runs 全链路
LLM 调用失败 看 agent_runs.error；临时设 *_SKIP_LLM=1 兜底
合规 REVIEW 一直堆 多半 LLM 不可用走了保守 fallback；批量 /admin/day4/recheck/:id
封面下载 403 反盗链：在 source.config 里加 referer / cookie
发布后站点不更新 检查 WEB_URL 和 REVALIDATE_SECRET；看 API 日志的 revalidate failed
有任务堆 failed scripts/inspect-failures.ts 看原因；retry-failed.ts 重试；clear-failed.ts 清掉
