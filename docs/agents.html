1source-scoring · 信源打分

入口
scoreAllSources() · workers/source-scoring/scorer.ts
触发
auto-pipeline · 手动 POST /admin/day5/score-now
LLM
无
状态变更
不动 items；只更新 sources 表
handoff
无下游

实现方式

纯 SQL，单一事务。一条 CTE 把每个 source 的指标聚合出来，按公式打分 + 写回。

聚合的指标

信号来源
total / published / compliance_fail / compliance_reviewitems 按 source_id 分组聚合
recent_ingesteditems.created_at > NOW() - 7 days
last_fetch_atsources.last_fetch_at
week_pv / week_revenueanalytics_daily JOIN items WHERE date >= CURRENT_DATE - 7

打分公式

score = 50
      + published × 2                                // 质量
      + (近 2 天有抓 ? 10 : 7 天内 ? 0 : -10)         // 新鲜度
      + min(15, recent_ingested)                     // 活跃度
      - compliance_fail × 5 - compliance_review × 2  // 风险扣
      + PV 加分 (0/3/6/10 阶梯, 阈值 100/1000/10000)
      + 收入加分 (0/3/5 阶梯, 阈值 $1/$10)
→ clamp(0, 100)

风险等级 + 状态自动调整

  • comp_fail ≥ 5 → risk_level = high
  • comp_fail ≥ 2 || comp_review ≥ 5 → risk_level = medium
  • comp_fail ≥ 20 → status = blacklist（强制拉黑）
  • score < 20 → status = paused（自动暂停）
  • status = inactive 永远不被自动改

写回字段

sources.score / risk_level / stability / status

2ingestion · 采集

入口
ingestSource(sourceId) · fanout() · workers/ingestion/index.ts
触发
cron 0 * * * * · POST /admin/ingest/fanout · POST /admin/ingest/source/:id
LLM
无
状态变更
新增 raw_items + items（status=INGESTED）
handoff

两种 job

  • kind: 'fanout' — 遍历所有 active 源，按 grayscale_pct 概率决定本轮是否采，命中的 enqueue 一条 kind: 'ingest'
  • kind: 'ingest' — 真干活，跑 ingestSource(sourceId)

支持的 platform 适配器

platform数据来源
rss标准 RSS / Atom
html列表页 + 跳详情（Readability 解析）
redditsubreddit JSON API
blueskyAT Protocol
xX / Twitter（需 cookie）
knit · json-2ksg图集站专项
sitemap-images站点 sitemap 图片源

对每条候选的处理流水

  1. 算 dedupeKey = sha256(platform:externalId)
  2. 第一层去重：urlAlreadySeen(sourceId, key) — 命中 → dupUrl++ 跳过
  3. 内容获取分支：
    • 适配器直给 text（≥20 字）→ 直接构造最小 Cleaned，跳 Readability
    • 否则 → clean(html, url) 走 Readability 抽正文 + 收图（<200 字 → cleanFail++）
  4. contentHash = sha256(normalize(content))
  5. 第二层去重：contentAlreadySeenForSource(sourceId, contentHash) — 命中 → dupContent++
  6. 算 simhash(content) → 第三层去重：nearestSimhash(sourceId, fp)，汉明距离 ≤ 3 → dupContent++
  7. persistIngested(...) — 一个事务里 insert raw_items + items + 更新 sources.last_fetch_at
  8. enqueue classify-title__<itemId>（jobId 去重并发）

容错

  • AdapterAuthError → 不抛，设 stats.authFail = true + authStatus / authReason，工作台高亮
  • pg 23505（unique violation，并发抓同 dedupe_key）→ 当作 dupUrl
  • 其他异常 → stats.errors++ + warn log

返回 stats

{
  candidates, ingested,
  dupUrl, dupContent, cleanFail, errors,
  authFail?, authStatus?, authReason?
}

3classify-title · 分类 + 起标题

入口
classifyTitleOne(itemId) · workers/classify-title/index.ts
触发
ingestion enqueue · 重跑 POST /admin/day3/reclassify/:id
LLM
haiku（分类）+ sonnet（标题）
状态守门
仅 INGESTED / CLASSIFIED / TITLED
handoff
enqueue cover__<itemId>

最短长度门

  • 全 SKIP_LLM → 内容 ≥ 10 字
  • 否则 → 内容 ≥ 40 字
  • 不够 → throw new Error('content too short')

Step 1 · 分类（仅 status=INGESTED 跑）

模式实现
LLM（默认）classify() · model = CLASSIFICATION_MODEL ?? 'haiku' · categorize.ts
规则降级classifyByRules({title, content}) — 关键词匹配映射到 taxonomy

LLM 通过强制 toolUse 输出 strict JSON：{ category, tags[], keywords[] }

写库后 INGESTED → CLASSIFIED

Step 2 · 起标题（总是跑）

LLMgenerateTitle() · model = TITLE_MODEL ?? 'sonnet' · 生成 N 个候选 + 选最优 + 摘要
规则降级generateTitleByRules({originalTitle, content}) — 沿用原标题 + 截前 220 字摘要

输出：{ candidates[], best_index, summary }

slug 生成

makeUniqueSlug(best, itemId) · slug.ts

  • 中文 → 拼音 ASCII
  • 拼接 <stem>-<6 位 itemId hex>，确定性：同 itemId+title → 同 slug
  • 防 unique 冲突重试

写回

title / summary / slug / title_version += 1 / status = TITLED

遥测聚合：两步的 token / cost / model 汇总后一并写 agent_runs，model 字段拼成形如 "rule:keyword+rule:original-title"。

4cover · 封面

入口
coverOne(itemId) · workers/cover/index.ts
LLM
可选（封面文案 caption）
状态守门
仅 TITLED / COVERED
handoff
enqueue compliance__<itemId>

关键查询（JOIN 三张表）

SELECT i.id, i.status, i.title, r.media_urls, s.platform, s.config
FROM items i
JOIN raw_items r ON r.id = i.raw_item_id
JOIN sources s   ON s.id = i.source_id

挑图策略

  • 默认 wantN = 1（单封面）
  • platform = html → wantN = 6（图集）
  • 调 pickTopN(media_urls, wantN, hint) · cover/select.ts

反盗链头部（按 platform 选）

platformRefererCookie
2ksghttps://uib.2ksg.com/（可被 config.referer 覆盖）—
knithttps://xx.knit.bid/config.cookie
xhttps://x.com/config.cookie
其他—（UA = ch-agents/0.1）—

单图打分

  • 下载（timeout 15s · ≤6 MB · validateStatus < 400）
  • sharp(buffer).metadata() 读宽高 + format
  • 跳过 width < 400 || height < 260（tracking 像素 / 图标）
  • 长宽比 < 0.5 或 > 3 → 系数 × 0.25
  • score = width × height × aspectPenalty

有 picks → 上传 S3

  • 主图：renderSizes(buffer) 出多尺寸（card / 等），路径 covers/<itemId>/<size>.jpg
  • 图集额外：covers/gallery/<i>/<itemId>/<size>.jpg
  • bucket 自动确保存在 + 公开读 policy（MinIO dev）

封面文案

COVER_SKIP_LLM=1cover_copy = item.title · model = "rule:title"
LLMgenerateCaption(item.title) · 失败不阻塞（cover_copy = null）

写回

cover_url（主图 card 尺寸）/ cover_sizes（JSON，含 gallery）/ cover_copy / status = COVERED

无 picks 的情况：状态仍然推到 COVERED，但 cover_url / cover_copy / model 都是 null。下游 compliance 不依赖 cover 字段，可以继续。

5compliance · 合规审核

入口
complianceOne(itemId) · workers/compliance/index.ts
LLM
sonnet（默认）· toolUse 强制结构化
状态守门
COVERED / COMPLIANCE_PASS / COMPLIANCE_REVIEW / COMPLIANCE_FAIL
handoff
仅 PASS → enqueue publish__<itemId>

L1 · 正则黑名单

compliance/blacklist.ts，跑在 ${title}\n\n${content} 上。3 类规则：

category模式举例
politics_sensitive （空，留位给监管对齐）
nsfw_explicit 调教/淫荡/裸体/无码/福利图 等关键词； [写真]...NN P 图集模式； (美胸|大尺度)...NN P 组合模式； hardcore porn；露骨色情
copyright_watermark 版权所有,未经授权不得转载；© 2024 ... all rights reserved；shutterstock watermark

返回 BlacklistHit[]。只要命中就跳过 L2，黑名单永远赢。

L2 · LLM 6 维度打分

仅在 L1 干净 + 未 SKIP_LLM 时跑。compliance/score.ts

6 个维度（每维 0-3）

  • 政治敏感 — 涉及政治人物 / 敏感事件 / 颠覆性言论 / 民族宗教冲突
  • 色情低俗 — 露骨性描述 / 擦边球 / 低俗猎奇
  • 暴力恐怖 — 暴力教唆 / 恐怖袭击细节 / 血腥描写
  • 版权争议 — 直接搬运 / 未去水印 / 未授权段落
  • 医疗夸大 — 无证医疗建议 / 包治百病 / 虚假疗效
  • 金融诱导 — 非法集资 / 保本保收益 / 荐股荐币

调用细节

  • System prompt 缓存（cache: true）
  • maxTokens = 512，temperature = 0
  • content 截断到 1800 字喂模型
  • toolUse 强制输出 RiskScores = { scores, reasons }，reasons 仅对 ≥2 给一句 ≤50 字理由
  • LLM 失败 → risk = undefined（不抛错）

Decide · 决策表

输入决定trigger
黑名单命中COMPLIANCE_FAILblacklist
risk = undefined（LLM 跳过 / 失败）COMPLIANCE_REVIEWllm_review
max(scores) ≥ 3COMPLIANCE_FAILllm_reject
max(scores) ≥ 2COMPLIANCE_REVIEWllm_review
否则COMPLIANCE_PASSpass
SKIP_LLM 特殊处理：L1 干净 + COMPLIANCE_SKIP_LLM=1 时合成全 0 分，自动 PASS（否则会因 risk=undefined 进 REVIEW）。

写回

status / compliance_status: PASS|REVIEW|FAIL
risk_tags: 命中维度数组
compliance_reasons: JSON {
  trigger, maxScore,
  blacklist: BlacklistHit[],
  scores, reasons
}

UPDATE items SET
  status = 'PUBLISHED',
  slug = $slug,
  published_url = `${SITE_URL}/a/${slug}`,
  published_at = COALESCE(published_at, NOW())  -- 重发不重置时间戳
WHERE id = $1

fire-and-forget：POST 到 ${WEB_URL}/api/revalidate，带 x-revalidate-secret，timeout 5s。失败不阻塞发布。

paths = ['/', '/a/<slug>', '/sitemap.xml']
+ category 存在 → '/category/<encoded category>'

返回

7distribution · 社媒分发人工闸口

入口
distributeOne(itemId, channel='twitter') · workers/distribution/index.ts
触发
仅人工：POST /admin/day6/distribute/:id · POST /admin/day6/distribute-all
LLM
sonnet（默认）/ 规则版（DISTRIBUTION_SKIP_LLM=1）
状态变更
items: PUBLISHED → DISTRIBUTED；写 distribution_tasks

前置校验

  • WHERE status = 'PUBLISHED' — 否则 skipped
  • published_url 必须有
  • distribution_tasks WHERE item_id + channel 已存在 → 跳过（幂等）

改写策略

模式实现
DISTRIBUTION_SKIP_LLM=1 规则版：tags 取前 3 拼 hashtag；标题按 280 - 23（t.co）- tags 长度 截断 + …；末尾拼 published_url
默认（sonnet） system prompt 要求：≤280 字符、1-2 句、2-3 hashtag、不要 【】 格式；
maxTokens = 256，temperature = 0.7；system prompt 缓存

LLM 输入字段

title / category / tags（前 5）/ summary / published_url

写回

INSERT INTO distribution_tasks (item_id, channel, copy, status='pending');
UPDATE items SET status='DISTRIBUTED' WHERE id = $1;
真实推送由外部完成：这一步只生成文案 + 入库待办。实际推送到 X 的动作由外部 worker 消费 distribution_tasks WHERE status='pending'，人工通过 POST /admin/pipeline/confirm-distribution/:taskId 确认完成。

返回

{ channel, copy, model, costUsd }

9公共横切层

withRun() · 统一审计

packages/agents/src/runner.ts

所有 8 个 agent 调用都包在 withRun({agent, itemId, inputHash}, fn) 里：

  • 开始前插入 agent_runs 行（status=running，记录起始时间）
  • 成功 → UPDATE 写 output / model / token / cost / latency
  • 失败 → UPDATE 写 error（截断 2000 字符）+ latency
  • 异常会被重新抛出，BullMQ 仍按 attempts 重试

callClaude() · LLM 调用层

packages/agents/src/anthropic.ts

名字虽叫 Claude，实际走 Groq（OpenAI 兼容协议）。统一封装：

  • 3 个模型别名：opus / sonnet / haiku → 由 GROQ_MODEL_LARGE / MEDIUM / SMALL 映射
  • 支持 toolUse 强制 JSON（用 system prompt 注入 schema + json_object 模式）
  • 自动重试（408 / 429 / 5xx），指数退避，maxRetries 默认 3
  • 统一返回 { text, toolUse, usage, costUsd, latencyMs }
  • cost 按 Groq 定价表算

BullMQ 队列层

packages/agents/src/queue.ts

重试3 次，指数退避（500ms 起）
保留成功 7 天 / 5000 条；失败 30 天
jobId 模板<agent>__<itemId> — 天然去重，并发触发只跑一次
concurrencyingestion=6 · classify-title=1 · cover=6 · compliance=1 · publishing=2 · distribution=3 · 其他=默认
